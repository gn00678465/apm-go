# apm-go architecture

How apm-go is built: the layers, the direction dependencies may point, the data flow of each major command, the cross-cutting mechanisms every layer shares, and the gates a change must pass. Every structural claim is anchored to code as `path:line`. Product facts and the terminal UI design live in [PRODUCT.md](PRODUCT.md); engineering and testing rules live in [AGENTS.md](AGENTS.md). Each topic lives in exactly one of the three files.

Layout: `cmd/apm-go/` holds one file per cobra subcommand; `internal/` holds the libraries listed in §2; `tools/parity/` is the output-contract runner (§5); `spec/conformance/` holds spec tables that tests read at run time.

Leaves (import nothing in-module): `archive`, `credsec`, `experimental`, `pack`, `rootfs`, `security`, `semver`, `ux`, `version`, `yamlcore`.

**Dependency rules.** A new edge that the graph lacks is a design change; get a ruling before adding it.

- `yamlcore` is the floor for all YAML and depends only on `go.yaml.in/yaml/v4`; `manifest` depends only on `yamlcore`; `lockfile` only on `manifest` and `yamlcore`.
- `deploy` reads only what is already on disk under `apm_modules/`; fetching (`gitops`, `registry`) stays above it. `resolver` fetches through the injected `resolver.PackageLoader` interface (`internal/resolver/types.go:24`), which keeps `gitops` out of it.
- Terminal output is emitted by `cmd/apm-go`, `pack/bundle`, and `pack/pluginmanifest`; every other package returns diagnostics or errors for the command layer to print.
- `security` has two callers: `pack/bundle` and `cmd/apm-go/audit_content.go` (§4).

## 3. Data flows

### 3.1 `apm-go install`

```mermaid
sequenceDiagram
  participant C as cmd/apm-go/install.go
  participant M as manifest
  participant R as resolver
  participant L as registry.Loader → gitops.RealPackageLoader
  participant D as deploy
  participant K as lockfile
  C->>C: frozen? (flag or CI) install.go:250
  C->>M: yamlcore.SafeLoad + ParseManifest install.go:317
  C->>K: ParseLockfile install.go:638
  alt frozen
    C->>K: CheckFrozenInstall :651 / planFrozenDeploy :662 (VerifyDeployedState)
    C->>L: registry: VerifyArchiveBytes :727 + archive.SafeExtract :730
    C->>D: locked files not on disk: frozenDeployPlan.run :828 → deploy.Run in a temporary directory, then in place; no lock write
  else resolve
    C->>R: Resolve(m, lock, tags, regLoader, cfg) install.go:931
    R->>L: PackageLoader.LoadPackage
    L-->>L: registry dep: HTTP download → hash check → SafeExtract loader.go:48
    L-->>L: otherwise: clone under ApplyCloneEnv clone.go:41
  end
  C->>D: ResolveTargets :1922 → deploy.Run :1991
  D->>D: Adapters[target] deploy.go:420
  C->>K: buildLockfile :1724 → installRun.finish install_report.go:320 (IsSemanticEqual + lockIsCanonical :332 → WriteLockfile :335 → writeLockfileBytes :339)
```

1. `installCmd` assembles `installDeps` (`cmd/apm-go/install.go:37`): `tags` is `gitops.RealTagLister`, `loader` is `gitops.RealPackageLoader` (`:171-172`). Tests inject both.
2. `runInstall` (`:221`) decides frozen first; with no flag and `lockfile.IsCIEnvironment()` true it forces frozen and prints an info line (`:239-242`). A frozen install with no `apm.yml`, `--global` included, goes on with an empty manifest and creates no file (`:295`). A frozen install checks the deployed files with `lockfile.VerifyDeployedState` under the deploy root (`deployDir`, which is `HOME` for `--global`; `.` otherwise) and reports the first violation, which is fixed because the violations are ordered by `lock.Dependencies`, then local content, each by ascending path. A locked file is not on disk when its violation has no observed hash and `os.Lstat` finds nothing at the path; a file with other content, a dangling symlink, an unreadable file and a directory are the other kind, and the first of those in that order is the error, with nothing written (`planFrozenDeploy` `cmd/apm-go/install_frozen_deploy.go:52`, called at `:650`). When every violation is a file that is not on disk, the frozen install deploys from the lock (issue #65). Before any write or network request the plan needs an `apm.yml`, a target (`deploy.ResolveTargets`; none is `errNoDeployTarget`, exit 2), and for each such path a target that governs it in the bucket that records it (`frozenTargetsGovern` `install_frozen_deploy.go:94`, `deploy.TargetsGovernPath`); without `apm.yml`, or for a path no target governs, the error is the `<missing>` violation of that path. After the source steps (A2) and (B), `frozenDeployPlan.run` (`install_frozen_deploy.go:113`, called at `:804`) copies each local-path direct dependency that has no `apm_modules/<key>` through the loader and builds the `resolver.ResolutionResult` from the lock's dependencies. It then tries the deploy in a temporary directory, which it removes when it returns: `deploy.Run` with that directory as the deploy directory and every other argument as the deploy in place has it (`:159`), so a `--global` trial is a symlink deploy too: a symlink deploy records the symlinks inside a skill's source directory, which a copy deploy skips. The links of a trial point at the sources, and removing the directory removes the links only. Each hash the trial returns has to be the lock's hash for that path in the same bucket (`frozenDeployMatchesLock` `install_frozen_deploy.go:221`; the digests are compared as `VerifyDeployedState` compares them, so a lock with a bare hex digest matches): another hash, or a path the lock does not have (`expected <not in lockfile>`), is a content-integrity error, so sources that changed after the lock was written fail the install; and each locked path that is not on disk has to be among the trial's paths of the bucket that records it (`missingDeployed` `install_frozen_deploy.go:196`), else the error is its `<missing>` violation. A frozen install that fails up to here leaves every path under the deploy root outside `apm_modules/` as it was; the sources this run put in `apm_modules/` stay, as step (B) leaves them. Only then `deploy.Run` runs in place as `deployAndFinalize` calls it (`:176`), `frozenDeployMatchesLock` runs on its result, and `VerifyDeployedState` runs once more. This path writes neither the lock nor `apm.yml` nor `.gitignore`, cleans no stale file, and prints only the frozen success line. `deploy.Run` writes a merged MCP config such as `.mcp.json` as it always does; that file is not verified. Deliberate deviation from the Oracle, whose `--frozen` checks the lock's structure and then runs an ordinary install (`commands/install.py:1758-1762`): it overwrites a changed deployed file and rewrites the lock when the sources changed. Its source step (B) calls the loader for git dependencies only, with a reference rebuilt from the lock entry; the reference of an entry with a `virtual_path` carries the `VirtualType` that parsing `apm.yml` gives that path (`manifest.VirtualTypeOf` `internal/manifest/depref.go:1553`, set at `:771`), because the loader takes only that directory for a subdirectory reference and the whole repository for a reference with no type. The rebuilt reference has no `Scheme`: the lock does not record one. The ref it passes is the entry's `resolved_commit`, so a subdirectory package is cloned at the commit the lock pins. (B) then verifies `tree_sha256` in `apm_modules/<key>` for each git entry with a commit, except a subdirectory package (`:791`), which has none and whose directory is not a checkout. a lock entry whose key starts with `_local/` (`localModulesKeyPrefix` `:3373`, a local-path dependency) is skipped like a `registry` or `local` source (`:748-755`). The current lock records a local package as `source: local`; the key check is for a lock written before issue #50, which records it as a git source with no source path, so the loader would delete the copy and clone it as a git dependency. Such a lock names the package `_local/<name>-<8 hex>` (`legacyLocalModulesKey` `:3322`). A frozen install reads it under that old key (`useLegacyLocalKeys` `:3358`, called at `:638`) and changes no file. A non-frozen install rewrites the whole lock in the current format (step 6), puts the package at `apm_modules/_local/<name>`, and deletes exactly the old directories the old lock names (`removeLegacyLocalModules` `cmd/apm-go/install_report.go:510`). `uninstall` finds the old key too (`uninstallRemovalKey` `cmd/apm-go/uninstall.go:208`).
3. A non-frozen install with a package and no `apm.yml` creates it first, as the Oracle does (`commands/install.py:1469-1498`; issue #81): `createInstallManifest` (`cmd/apm-go/install_bootstrap.go:94`, called at `install.go:293`) writes the bytes of `newManifestBytes` (`install_bootstrap.go:33`), which builds the file with `buildManifestNode` and validates it as `init` does, named after the project directory, or for `--global` after `HOME` (`manifestOwnerName` `:80`), with the `targets:` that `manifestTargetsFromTargetFlag` (`:148`, the Oracle's `manifest_targets_from_target_option`) derives from the raw `--target` tokens, and prints `Created <apm.yml>` and `Targets set: ...`. The rest of the run reads it as an existing `apm.yml`: `installRun.finish` writes the packages into it also when the lock does not change (`manifestCreated`, `install_report.go:344`), and when `runInstall` returns an error a deferred `removeCreatedManifest` (`install_bootstrap.go:113`, `install/transaction.py:37-72`) deletes it. An `apm.yml` that exists is never given a `targets:`. With no package and no `apm.yml` the install prints the Oracle's lines and exits 1 (`errNoManifest` `install_bootstrap.go:125`, called at `install.go:308`). `install --global --mcp` creates `~/.apm/apm.yml` the same way in `runMCPInstall` (`cmd/apm-go/mcpinstall.go:60`), with no comments, because the Oracle writes that file again with `yaml.safe_dump` (`install/mcp/command.py:189-194`), and with the targets the install configures as `targets:` (`mcpManifestTargets` `:230`: `deploy.ResolveTargets` of `--target`, `all` expanded, each target with an MCP adapter once, in order), as the Oracle writes its `supported_runtimes`; a failure before that write leaves no file, and one after it keeps the file, as in Oracle 0.33.0, whose MCP path has no install transaction (`install/mcp/command.py:189-194,312`); a project `install --mcp` still refuses a missing `apm.yml`. `apm.yml` then goes through `yamlcore.SafeLoad` → `manifest.ParseManifest` (`:306`); each direct dependency passes `manifest.CheckInsecureDependencyScheme` (`:604`). The string form and the object form `path:` share one test of what a local path is (`localPathOf` `internal/manifest/depref.go:1075`, the Oracle's `is_local_path`; called by `ParseDepString` and by `ParseDepDict` `:1104`) and read the same path, the value without its surrounding whitespace, because `install <local path> --skill` moves the string from one form to the other and it has to stay the same package. A value that starts with `//` and a UNC path (`\\host\share`) are not local paths: the string form refuses them with the Oracle's texts (`Protocol-relative URLs are not supported ...`, `errProtocolRelative`; `Use 'user/repo' ...`), and the object form refuses them, `path: dep` and `path: sub/dep` with the Oracle's `Object-style dependency ...` reason; a `path:` value that is empty or not a string gets `'path' field must be a non-empty string`. A local path may point above the project root (`../dep`), as in the Oracle; a package fetched from elsewhere cannot declare a local path at all (`isLocalFilesystemDep`, §3.1 step 4). Its last component, read as Python's pathlib reads it (as a Windows path when it has a backslash), has to be a name (`namesDirectory` `internal/manifest/depref.go:1087`, the Oracle's `reference.py:1812-1821`): `./`, `./.`, `./dep/..`, `/` and `../` are refused in both forms with the Oracle's `Local path '<path>' does not resolve to a named directory. ...`. Every command that parses `apm.yml` then ends with exit 1 before it writes anything; the text before the reason is apm-go's own, not the Oracle's transcript (`install`, `uninstall` and `update` print `validate apm.yml: dependency entry <N> (path: "<value>"): <reason>`). Because of this a `{path: x}` entry whose skill subset is reset is written back as the string `x` (`setEntrySkillSubset` `cmd/apm-go/install.go:3004`). When `install <local path>` adds a local entry, or sets or clears the skill subset of one, the path is written without the whitespace around it, as the Oracle writes it (`setEntrySkillSubset`, `newGitSkillEntry`, `persistPackagesToManifest`); an entry `install <local path>` matches with nothing to change in it keeps its bytes. A local-path dependency's `apm_modules` key and lock `repo_url` is `_local/<directory name>` (`normalizeLocalDep` `:3270`, `localModulesKey` `:3347`), the Oracle's layout. Two local packages with the same directory name are refused before anything is written (`localSources.add` `:3313`, called at `:351-363` for `apm.yml` and at `:505` for a package on the command line; `errLocalNameCollision` `:3302`; exit 1); this is a deliberate deviation from the Oracle (issue #50 ruling R6), which copies the second over the first and exits 0. The same call runs `gitops.CheckLocalCopy` (`internal/gitops/clone.go:454`) on each direct local dependency, so every refusal of a copy described in step 4 is decided before the first copy and leaves the copies of earlier packages as they were; `update` runs it on the dependencies of `apm.yml` before it clears or resolves anything (`cmd/apm-go/update.go:158`). The object forms `path:`, `git:` and `id:` read `targets:` into `DependencyReference.TargetSubset` through `parseDepTargets` (`internal/manifest/depref.go:1398`), a port of the Oracle's `parse_target_subset` (`models/dependency/subsets.py:59-100`) with its reason texts: the names are checked against `knownTargets` (`:1389`), the Oracle's `KNOWN_TARGETS`, which is wider than the targets apm-go deploys to, then lowercased, deduplicated and sorted; `git: parent` refuses the key. ## 4. Cross-cutting mechanisms

**ux.** `ux.Init` (`internal/ux/ux.go:33`) detects TTY, `NO_COLOR` (`:112`), and the CI variables `CI` / `GITHUB_ACTIONS` / `GITLAB_CI` / `BUILDKITE` / `TF_BUILD` / `JENKINS_URL` (`isCI` `:117-121`) once at startup, setting `richMode` (prompts) and `styleEnabled` (spinner animation). lipgloss degrades color per writer. Symbol vocabulary and frame rules: [PRODUCT.md § Terminal UI design](PRODUCT.md#terminal-ui-design).

**YAML round-trip.** Writes to `apm.yml` start from the original bytes, locate with `yaml.Node`, and replace only the affected region through `yamlcore.PatchMappingPath` / `PatchMappingPathCompact` / `SpliceSequenceElement` / `RemoveMappingKey` / `RebuildSequenceValueDropping`. Built on that: `manifest.RemovePackagesFromManifest` (`internal/manifest/remove.go:50`) and `RemoveMCPServersFromManifest` (`mcp_remove.go:34`). `apm.lock.yaml` is not patched in place: `lockfile.WriteLockfile` (`internal/lockfile/write.go:44`) serializes the whole file in the Oracle's layout, and `SerializeLockfile(lf, original)` (`:56`) carries over unknown fields and `x-*` keys from the original node; comments and the quote style of the old file are not kept. `SafeDumpManifest` (`yamlcore/safe.go:56`; PyYAML's layout) is for a brand-new `apm.yml`, the lock, and a block written through `PatchMappingPathCompact`.

**gitops secure environment.** Every git subprocess runs under `gitops.ApplySecureGitEnv` (`internal/gitops/secure_env.go:53`: credential prompts off, `GIT_ALLOW_PROTOCOL` allow-list, `GIT_PROTOCOL_FROM_USER=0`) or the clone-specific `ApplyCloneEnv` (`harden.go:68`). Call sites: `gitops/clone.go`, `gitops/tags.go`, `cmd/apm-go/doctor.go:60`, `marketplace/client_git.go:129,138`, `marketplace/authoring/refcheck.go:104`, `marketplace/authoring/refcheck_sha.go:218,232,286,397` (scratch rev-parse / fetch / init / show, each also pinned to `LC_ALL=C`), `marketplace/build/metadata.go:161-174`, `marketplace/build/reflister.go:87`, `tools/parity/preflight.go:235`. **Git URL rewrite safety.** A `url.<base>.insteadOf` rule in the user's git configuration changes where a network git subprocess connects. `gitops.ValidateURLRewriteSafety` (`internal/gitops/url_rewrite.go:169`; a port of the Oracle's check in `utils/git_env.py`) must pass before every one: it reads the effective configuration with `git config --null --show-scope --list` under `SecureGitEnv` (`readEffectiveGitConfig` `:197`; 10 s, then one 30 s retry), applies the longest matching rule (`resolveURLRewrite` `:264`), and judges the result (`validateResolvedURLRewrite` `:288`). No matching rule passes with no further check. A rule that selects remote-helper syntax, adds credentials, downgrades to HTTP or another insecure transport, rewrites a credential-bearing remote, moves a remote that git would send an authorization header to (`hasApplicableHTTPAuthorization` `:364`, with a second probe `git config --get-urlmatch http.extraHeader`) to another origin, or moves a network remote to another host is a `*URLRewriteError` (`:41`, with the Oracle's reason code); a configuration that cannot be read is a `*URLRewriteProbeError` (`:52`), which fails the operation. ## 5. Gates

**`go test ./...`** verifies Go-level correctness. Injection seams: `installDeps` `cmd/apm-go/install.go:37`, `doctorDeps` `doctor.go:35`, `ux.SetPromptSeamsForTest` / `SetTTYSeamsForTest` `internal/ux/testhooks.go:30,66`, `pluginjson.SetCommitHookForTest` `internal/pluginjson/testhooks.go:10`.

**Conformance tables (`spec/conformance/`)** are run-time inputs to tests, tracked in git:
- `depref-accept.json` → `internal/manifest/depref_conformance_test.go:56` (dependency-reference parsing table; regenerated by `tools/depref_conformance_gen.py`).
- `python-repr.json` → `internal/marketplace/python_repr_conformance_test.go:53`.

- `openapm-v0.1.md`, `cli-surface-parity-v0.27.0.md`, `cli-verification-checklist.md` are specification documents.
- The `oracle_commit` key in `depref-accept.json` and `python-repr.json` records which Oracle commit generated the fixture; no test compares it.

**Recorded Oracle output (`cmd/apm-go/testdata/pack_metadata_oracle/`)**: what the Oracle printed and wrote for `apm pack` with a canned remote-metadata outcome (a real fetch is network, so it cannot be a parity case). `tools/pack_metadata_oracle_gen.py` generates the records; `cmd/apm-go/pack_metadata_oracle_test.go` replays each against apm-go behind a fake `MetadataFetcher` and compares exit code, written files, fetch count, and stdout.

**Output contract — the parity gate (`tools/parity`).** The gate compares apm-go with the latest stable upstream release of the Oracle. The `parity` job in `.github/workflows/parity.yml` resolves that release's tag when it runs (`gh api repos/microsoft/apm/releases/latest`, which never returns a prerelease or a draft), checks out `microsoft/apm` at the tag, builds `bin/apm-go`, then runs `go run ./tools/parity -cases tools/parity/cases -out parity-out`; no Oracle commit is recorded in this repository, so a new upstream release can turn the gate red with no change here; before running it greps every `case.json` for `https://` and `github.com/` to confirm no network URL is referenced (cases run on local fixtures only); the check allows exactly the JSON string `"https://example.com/mcp"`, the `--url` value of `install --mcp`, and still blocks a longer string that starts with it. The `go-test` job in the same workflow is separate on purpose: green tests say nothing about the contract.

Runner:
- `Case` (`tools/parity/case.go:18`): `id`, `argv`, `stdin`, `env`, `setup_argv`, `path_prepend`, `timeout_s`, `forbid_substrings`, `expected_taxonomy`, `waiver`; `LoadCases` (`:100`) reads `cases/<id>/case.json` plus `fixture/`.
- Preflight (`runPreflight` `tools/parity/preflight.go:55`) records the Oracle checkout's commit, dirty state and `--version` in `run.json` and compares the commit with nothing; it fails the run only when the checkout's HEAD cannot be read or the Target binary is unusable.
- Each case runs in a fresh sandbox (new cwd and HOME, `sandbox.go`) with an allow-listed environment (`env.go`) via `runCaseSide` (`runner.go:18`); stdout, stderr, exit code, and the post-run file tree (`postRunTree` `runner.go:207`) are the evidence record.
- A case directory may hold `home_fixture/` next to `fixture/`: `Case.HomeFixtureDir` (`tools/parity/case.go:99`) finds it, and `newSandbox` (`sandbox.go:34`, called at `runner.go:19`) copies it into the sandbox HOME with the same `copyTree` as `fixture/` (`sandbox.go:60`; a symlink is copied as a symlink), on both sides and before `setup_argv`. A case can then start from state under `$HOME`, such as `~/.apm` for `deps list -g`; `.gitignore` re-includes `tools/parity/cases/*/fixture/apm_modules/` and `tools/parity/cases/*/home_fixture/.apm/apm_modules/`, which its `apm_modules/` rule would leave out of the repository. Its files are not in the pre-run snapshot, which covers cwd only; they appear as `home/...` entries of the post-run tree and are compared like any other file.
- `diffCase` (`diff.go:109`) normalizes first (`normalize.go:47`: sandbox paths, hex tokens, timestamp lengths; `normalizeStatusGlyphs` `:74` treats status-symbol shape as the one sanctioned glyph difference), then compares stdout, stderr, exit code, and tree; `--help` cases use semantic comparison (`help_semantic.go`). `normalizeStatusGlyphs` also reduces a status symbol directly after one of the two prefixes `"  "` and `"|  "` to one token for both shapes (`canonicalNestedStatusGlyphLine` `normalize.go:98`), for the symbols `+ > * i ! x` only; there the Oracle's `[*]` is the success class and equals apm-go's ` + `. A tree file's bytes are normalized before they are compared (`normalizedFileBytesEqual` `diff.go:413`), and in `cwd/apm.lock.yaml` alone the first top-level `apm_version:` line is replaced by a placeholder (`normalizeTreeFileContent` `normalize.go:221`; ruling R12), because each side writes its own version there.
- **Waiver** (`waiver.go:18`; `waivers.json`): `id`, `fields`, `tree_paths`, `taxonomy`, `reason`, `owner`, `eval_plan_ref`. `applyWaiver` (`diff.go:486`) counts a case waived only when the waiver covers every differing field; an unknown waiver id fails validation.
- **Baseline** (`baseline.go:40`; `baseline.json`): exact paths of global-state side-effect files, excluded from the tree comparison.
- `countUnwaived` (`diff.go:553`) > 0 returns an error and fails the job (`main.go:237`); `summary.txt` and `parity-out/` are printed and uploaded as an artifact either way.
- **Pending cases** (`tools/parity/cases-pending/`, currently none: the directory holds only its `README.md`; `tools/parity/cases/` holds 136 cases): a case recorded as a design deviation is kept there, out of the gate. `README.md` there requires such a case to have a **ticket** in `.scratch/parity-runner/issues/` and to return to `cases/` when the ticket closes.
- The runner has its own `go test` (`tools/parity/*_test.go`) and a `-selftest-only` fault-injection self-check (`main.go:45-54`, `selftest.go`).

**Release.** `release.yml` requires the tagged commit to be an ancestor of `origin/main` (fail-closed) and injects the tag into `Version` via `-ldflags -X` (`internal/version/version.go:14`); tags containing `-` are marked prerelease.
