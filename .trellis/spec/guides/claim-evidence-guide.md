**這張表在 2026-07-28/29 的 `07-28-marketplace-plugin-parity` 規劃中失效了。**

該 task 有四個斷言被外部稽核推翻，逐字為：

| 被推翻的斷言 | 原文位置 | 推翻證據 |

| 「本專案**設計較佳**，**無缺口**」 | 同上 `:231` | `install.go:1620` 的 `deploy.Run` 早於 lockfile(`:1764`) 與 apm.yml(`:1777`)，仍會留下不一致狀態 |

## 規則：句型觸發，不是字眼觸發

只要一個句子**指涉程式碼**且屬於下列任一句型，就必須在**同一處**附上證據三件套。
不論用什麼措辭、什麼語言、有沒有用到舊詞表裡的字。

### 觸發句型

| 句型 | 例子（全部都要證據） |
|---|---|
| **比較** | 較佳 / 較差 / 優於 / 劣於 / 更安全 / 更快 / 比 X 好 |
| **等價** | 等價 / 一致 / 相同 / 對齊 / 無差異 / 行為相同 |
| **化約** | 純 X 層 / 只是 X / 僅為 X / 單純是 |
| **充分性** | 已覆蓋 / 足夠 / 不需要 / 沒必要 / 已處理 / 已驗證 |
| **不存在** | 無缺口 / 沒問題 / 不受影響 / 不會發生 / 沒有風險 |
| **量級** | 成本大 / 成本小 / 工程量大 / 微幅 / 一行就好 / 量級不同 |
| **時序** | 延後 / 之後再做 / 另開 / 不在此範圍 |
| **因果歸因** | 根因是 X / 是 X 造成的 / 因為 X 才失敗 / 這是 X 的問題 |
| **風險接受** | 風險可接受 / 機率很低 / 實務上不會發生 / 這個 race 無所謂 |

舊詞表的九個詞全部落在上表之中，所以**這份守則向下相容**，不需要同時維護兩套。

### 「因果歸因」與「風險接受」為什麼要獨立成類（2026-07-29 補）

這兩類是 codex 對抗性稽核找出的漏網之魚 —— 我請它舉一個
「會造成同類失誤但不落在原本七類裡」的反例，它舉出：

> 「這次資料遺失的**根因是 DNS 抖動**。」

這句能讓調查**當場停止**，但它不是比較、不是等價、不是化約、不是充分性、
不是不存在、不是量級、也不是時序。若歸因錯了，真正的持久化 bug 就被放過。

「此競態風險可接受」同理 —— 它把一個未量測的機率當成已知，用來關掉問題。

**兩類的證據要求**：
- 因果歸因：必須有能**排除其他候選原因**的證據，不能只有「符合現象」。
  單一巧合不是因果。
- 風險接受：必須有**觸發條件與影響範圍**，外加「誰承擔」。
  沒量測過的機率不能當低機率用。

### 證據三件套（沿用 `AGENTS.md` §5）

1. **`file:line`** —— 實際打開讀過的路徑。不是「應該在」，是讀過的位置。
2. **威脅模型 / repro / 反例** —— 誰可控、可得什麼；或重現步驟；或一個具體反例。
3. **成本估計** —— 當結論是「延後 / 需大改 / 成本大」時必附。

### 只有形容詞 = 缺陷，不是結論

不確定時只能寫「**未驗證**」。「延後」「較佳」「等價」都是 claim，不是免死的範圍決定。

## 反向檢查：這個判斷是靠讀哪段程式碼得到的？

寫下任何觸發句型之前，先回答一句話：

> **「如果我錯了，哪一段程式碼會證明我錯？我讀過它了嗎？」**

四個失效案例套進來全都當場現形：

- 說「`--dev` 成本大」→ 會推翻我的是持久化那段 → `install.go:2012-2035` → **沒讀過** → 不能寫
- 說「優於上游」→ 會推翻我的是 add 的選項結構 → `editor.go:413-422` → **沒讀過** → 不能寫
- 說「純呈現層」→ 會推翻我的是兩邊的 result model → `refcheck.go:131` vs `check.py:130-225` → **沒比對過** → 不能寫
- 說「fail-closed 較佳」→ 會推翻我的是部署寫入時機 → `install.go:1620` → **沒讀過** → 不能寫

讀不到、讀不完、沒時間讀 → 寫「未驗證」，不要寫形容詞。

## 完成宣告（completion claim）的兩條硬規矩

「做完了」是充分性句型裡最貴的一種，另外加兩條：

### 規矩 1 —— 未經外部驗證不得宣告完成

任何「完成 / 齊了 / 可以進下一階段」都必須附一個**外部檢查**的結果：
`codex exec -s read-only` 的稽核，或一個 fresh-context 的 subagent。

沒有外部檢查時，只能寫「**我做到 X，尚未驗證**」。

理由（`.trellis/workflow.md:304`）：同模型自我重讀與原錯誤**相關**——
會合理化某個判斷的模型，重讀時會再合理化一次。自我複查不算驗證。

### 規矩 2 —— 完成宣告一律附可執行證據

不准用形容詞收尾。每個宣告附上**實際跑過的指令與輸出**，讓對方能自己重跑推翻。

- ❌ 「三份文件都齊了，品質良好」
- ✅ 「`grep -c '^- \[ \]' checklist.md` → 62；`go build ./...` → exit 0；codex 稽核 → 5 阻斷級，已修 5」

## 偵測

任何人（或任何 reviewer agent）看到上表任一句型而旁邊沒有證據三件套，即為缺陷。
且它本該被寫作當下的反向檢查擋下，不該靠事後稽核抓。
