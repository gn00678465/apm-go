# 17 — `pack` flag/feature parity (spun out of ticket 13)

**What to build:** Implement the `apm pack` flags apm-go's `pack` command does not expose at all today, so `pack --help`'s `help_semantic` diff closes to just the ticket-07 `--format` description sentence.

**Blocked by:** nothing (each flag below is close to independent; `-o/--output` is the cheapest, `--archive`/`--check-versions`/`--check-clean` are real feature work). **Status:** open.

**Origin:** ticket 13 ("`pack` success output + `--help` parity"). That ticket's own written finding assumed `pack --help`'s `help_semantic` diff was empty except the ticket-07 `--format` deviation sentence. Verifying this directly (`diff/pack-help.json`, both sides' live `--help` output) found the assumption was wrong: apm-go is missing **nine** flags entirely, several representing real unimplemented features, not wording drift. Per the project's Scope rule (`.scratch/parity-runner/README.md`, added after ticket 11), a real finding outside a ticket's written acceptance criteria is spun out to its own ticket rather than chased inline — ticket 13 closes on its own three findings (success-output line set, relative paths, usage-error boilerplate) with this one recorded, not blocked on it.

## The finding

`apm-go pack --help` vs the pinned Oracle's `apm pack --help` (`commands/pack.py`'s `@click.option` decorators), verified directly:

| Flag | Oracle | apm-go | Note |
|---|---|---|---|
| `-o`, `--output PATH` | ✅ (default `./build`) | ❌ | `runBundleProducer` hardcodes `OutputDir: filepath.Join(".", "build")` — cheapest fix, no new feature, just wire a flag through. |
| `--archive` | ✅ | ❌ | Real feature: produce a `.zip` (or `.tar.gz`) instead of a directory. `internal/pack/bundle` has no archive-writing path at all yet. |
| `--archive-format [zip\|tar.gz]` | ✅ (default `zip`) | ❌ | Depends on `--archive` existing first. |
| `-t`, `--target TARGET` | ✅ (deprecated, informational-only metadata) | ❌ | Oracle docs it as already deprecated/ignored by install — low-risk to add as a pure metadata field once the plumbing exists. |
| `--check-versions` | ✅ | ❌ | Release gate: verify per-package versions against `marketplace.versioning.strategy`; exits 3 on misalignment. Real feature (`bundle/packer.py`'s version-alignment report). |

| `--format`'s description | ✅ (Oracle's own wording) | ✅ (Oracle's wording + one ticket-07-sanctioned trailing sentence: "apm-go currently implements only the Claude plugin bundle; agent-plugin and apm are accepted but refused.") | The ONE deviation ticket 13's finding correctly named — already fine, not part of this ticket. |

Also: the pack command's `Long` description text is a completely different, apm-go-authored paragraph (`packCmd()`'s own three-bullet summary of the three producers) rather than the Oracle's `_PACK_HELP` docstring (usage examples, exit-code table). Matching this is cheap (pure text) but pointless to do in isolation while 8 flags are still missing — the `help_semantic` diff will stay large regardless until the flags above exist. Fold the description-text fix into whichever of the flag items above is tackled first, not as a standalone pass.

Also (ticket 13 attempt 2, eval-ticket-13.md finding 2): **unknown-flag wording/suggestions are part of this same Click-parity surface.** Verified directly: `apm pack --bogus` on the pinned Oracle prints `No such option: --bogus Did you mean --verbose?` (Click's own "did you mean" suggestion machinery, diffing the bad flag against every registered option), while apm-go's cobra layer produces the structurally different `unknown flag: --bogus` with no suggestion at all. Same story for a flag missing its argument on anything other than the verified `--format` case (e.g. a shorthand like `-m`): cobra's raw message shape (`flag needs an argument: 'm' in -m`, reformatted by `setBundleFormatFlagErrorFunc` into `Option ''m' in -m' requires an argument.`) has never been checked against the Oracle's own Click wording for that flag and is likely wrong too (its embedded literal quotes look like a cobra-ism, not something Click would produce). Ticket 13 attempt 2 deliberately left ALL of this untouched (reverted to the exact pre-ticket-13 `[x] <cobra message>` shape, `TestRootError_UnverifiedFlagErrorsMatchPreTicket13Shape` in `cmd/apm-go/root_error_test.go` locks it down) rather than guess at a Click-compatible reimplementation. A real fix here likely means a shared "did you mean" suggestion helper (Levenshtein-ish nearest-flag-name matching) plus auditing every flag's own missing-argument wording against its Oracle counterpart, not a blanket string substitution.

### Phase 2 (2026-08-26): `--archive`/`--archive-format`

Mandatory upfront research (per the orchestrator's explicit instruction, not skipped): traced the Oracle's full archive call chain (`commands/pack.py` → `core/build_orchestrator.py`'s `BundleProducer.produce()` → `bundle/packer.py` → `bundle/claude_plugin_exporter.py` → `bundle/plugin_exporter.py`'s `export_plugin_bundle`, the real real-run/dry-run archive-handling site) down into `utils/archive.py`'s `write_zip_archive`/`write_tar_archive`, and probed `--archive-format`'s exact Click semantics live against the pinned Oracle (Choice case-sensitivity, the `"  [default: zip]"` auto-suffix via direct Click introspection, the invalid-value/missing-argument/no-effect-without-`--archive` error shapes, and validation ordering when multiple conditions apply at once).

- **`--archive`**: new boolean flag, exact Oracle help text (`commands/pack.py:184-194`). When set, `bundle.Produce` (`internal/pack/bundle/producer.go`) compresses the already-built bundle directory into a single archive file and removes the intermediate directory, mirroring `export_plugin_bundle`'s real-run sequence exactly: build directory → embed lockfile → archive → `shutil.rmtree(bundle_dir)` → report the ARCHIVE path (not the directory) as the bundle path. Dry-run reports the *projected* archive path without writing anything, matching the Oracle's own dry-run branch.
- **`--archive-format [zip|tar.gz]`**: new flag, exact Oracle help text including the baked-in `"  [default: zip]"` suffix (`commands/pack.py:195-205`) — same "empty pflag default + literal baked-in text" pattern as `-o`/`-t` (phase 1), reusing `bundleFormatChoiceValue` for the `[zip|tar.gz]` metavar. Unlike `--format`, this Choice is **case-sensitive** with no aliasing (`--archive-format ZIP` rejected, verified live) — validated by a new, separate `validateArchiveFormatChoice`, not `coerceBundleFormat`. The Oracle's own validation ORDER was verified live: Click's Choice check (parse-time) always fires before the function-body-level "no effect without `--archive`" check, even when both conditions are true simultaneously — apm-go's `RunE` replicates this exact order. The "no effect without `--archive`" `UsageError` (`commands/pack.py:329-337`, interpolating the given format value) and the missing-argument bare-usage-error shape (verified live to be byte-identical to `--format`'s own, so `setBundleFormatFlagErrorFunc` was extended to cover `--archive-format` too — a narrow, directly-verified addition, not a broadening to any other untested flag) are both replicated.
- **Archive-writing implementation** (`internal/pack/bundle/archive.go`, new file): `writeZipArchive`/`writeTarGzArchive` mirror `write_zip_archive`/`write_tar_archive` exactly — sorted directory walk, symlinks and non-regular-files skipped, every entry prefixed with the bundle directory's own base name (`"<name>-<version>/<relpath>"`), permission bits preserved via `zip.FileInfoHeader`/`tar.FileInfoHeader`. `-o`/`--output`'s interaction confirmed correct: it is the *directory* the archive lands in, not the archive's own path (`projectedArchivePath` mirrors `projected_archive_path`).
- **Security invariants** (explicit instruction: reuse `internal/archive`'s existing write-direction-equivalent invariants, don't open a new rule set): exported a new `archive.ValidatedRelPath` from `internal/archive/extract.go` — the exact same absolute-path/`".."`-segment check `SafeExtract`/`SafeExtractZip` already enforced inline, now a single shared function both the pre-existing extraction side AND the new archive-writing side call, refactoring `extract.go`/`zip.go`'s own inline duplicate logic to call it (zero behavior change, confirmed via the pre-existing `internal/archive` test suite passing unchanged). Every computed archive entry name is re-validated through it as defense-in-depth before being written. Symlinks inside the bundle directory are never followed into the archive (skipped, matching the Oracle's own `is_symlink()` skip) — verified with a real symlink pointing outside the bundle directory in a new unit test.

## Suggested order (cheapest/most isolated first)

1. `-o`/`--output` (wire an existing hardcoded value through a flag; no new logic).
2. `-t`/`--target` (pure metadata field, Oracle already treats it as ignored/deprecated).
3. `--archive`/`--archive-format` (real feature, but self-contained: an archive-writing step after the existing directory bundle is built).
4. `--legacy-skill-paths` (a deploy-path variant, likely shares code with existing per-target skill placement logic).
5. `--check-versions`/`--check-clean` (release gates — depend on `marketplace.versioning.strategy` config and a temp-regenerate-and-diff mechanism; more design work).
6. `--json` (touches every success/error path in `pack.go`; do last so its envelope shape can capture whatever the other flags added).
