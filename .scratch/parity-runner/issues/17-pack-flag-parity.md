# 17 — `pack` flag/feature parity (spun out of ticket 13)

**What to build:** Implement the `apm pack` flags apm-go's `pack` command does not expose at all today, so `pack --help`'s `help_semantic` diff closes to just the ticket-07 `--format` description sentence.

**Blocked by:** nothing (each flag below is close to independent; `-o/--output` is the cheapest, `--archive`/`--check-versions`/`--check-clean` are real feature work). **Status:** open.

**Origin:** ticket 13 ("`pack` success output + `--help` parity"). That ticket's own written finding assumed `pack --help`'s `help_semantic` diff was empty except the ticket-07 `--format` deviation sentence. Verifying this directly (`diff/pack-help.json`, both sides' live `--help` output) found the assumption was wrong: apm-go is missing **nine** flags entirely, several representing real unimplemented features, not wording drift. Per the project's Scope rule (`.scratch/parity-runner/README.md`, added after ticket 11), a real finding outside a ticket's written acceptance criteria is spun out to its own ticket rather than chased inline — ticket 13 closes on its own three findings (success-output line set, relative paths, usage-error boilerplate) with this one recorded, not blocked on it.

## The finding

`apm-go pack --help` vs the pinned Oracle's `apm pack --help` (`commands/pack.py`'s `@click.option` decorators), verified directly:

| Flag | Oracle | apm-go | Note |
|---|---|---|---|
| `-o`, `--output PATH` | ✅ (default `./build`) | ❌ | `runBundleProducer` hardcodes `OutputDir: filepath.Join(".", "build")` — cheapest fix, no new feature, just wire a flag through. |
| `--archive` | ✅ | ❌ | Real feature: produce a `.zip` (or `.tar.gz`) instead of a directory. `internal/pack/bundle` has no archive-writing path at all yet. |
| `--archive-format [zip\|tar.gz]` | ✅ (default `zip`) | ❌ | Depends on `--archive` existing first. |
| `-t`, `--target TARGET` | ✅ (deprecated, informational-only metadata) | ❌ | Oracle docs it as already deprecated/ignored by install — low-risk to add as a pure metadata field once the plumbing exists. |
| `--check-versions` | ✅ | ❌ | Release gate: verify per-package versions against `marketplace.versioning.strategy`; exits 3 on misalignment. Real feature (`bundle/packer.py`'s version-alignment report). |
| `--check-clean` | ✅ | ❌ | Release gate: regenerate every marketplace output to a temp representation and diff against on-disk; exits 4 on drift. Real feature. |
| `--json` | ✅ | ❌ | Machine-readable JSON envelope to stdout, logs to stderr (`_emit_json_error_or_raise`, `BuildReport.failure_to_json_dict`). Touches every error/success path in `pack.py`. |
| `--legacy-skill-paths` | ✅ | ❌ | Deploy skill files to per-client paths instead of the shared `.agents/skills/` directory. |
| `--format`'s description | ✅ (Oracle's own wording) | ✅ (Oracle's wording + one ticket-07-sanctioned trailing sentence: "apm-go currently implements only the Claude plugin bundle; agent-plugin and apm are accepted but refused.") | The ONE deviation ticket 13's finding correctly named — already fine, not part of this ticket. |

Also: the pack command's `Long` description text is a completely different, apm-go-authored paragraph (`packCmd()`'s own three-bullet summary of the three producers) rather than the Oracle's `_PACK_HELP` docstring (usage examples, exit-code table). Matching this is cheap (pure text) but pointless to do in isolation while 8 flags are still missing — the `help_semantic` diff will stay large regardless until the flags above exist. Fold the description-text fix into whichever of the flag items above is tackled first, not as a standalone pass.

Also (ticket 13 attempt 2, eval-ticket-13.md finding 2): **unknown-flag wording/suggestions are part of this same Click-parity surface.** Verified directly: `apm pack --bogus` on the pinned Oracle prints `No such option: --bogus Did you mean --verbose?` (Click's own "did you mean" suggestion machinery, diffing the bad flag against every registered option), while apm-go's cobra layer produces the structurally different `unknown flag: --bogus` with no suggestion at all. Same story for a flag missing its argument on anything other than the verified `--format` case (e.g. a shorthand like `-m`): cobra's raw message shape (`flag needs an argument: 'm' in -m`, reformatted by `setBundleFormatFlagErrorFunc` into `Option ''m' in -m' requires an argument.`) has never been checked against the Oracle's own Click wording for that flag and is likely wrong too (its embedded literal quotes look like a cobra-ism, not something Click would produce). Ticket 13 attempt 2 deliberately left ALL of this untouched (reverted to the exact pre-ticket-13 `[x] <cobra message>` shape, `TestRootError_UnverifiedFlagErrorsMatchPreTicket13Shape` in `cmd/apm-go/root_error_test.go` locks it down) rather than guess at a Click-compatible reimplementation. A real fix here likely means a shared "did you mean" suggestion helper (Levenshtein-ish nearest-flag-name matching) plus auditing every flag's own missing-argument wording against its Oracle counterpart, not a blanket string substitution.

## Progress log

### Phase 1 (2026-08-26): `-o`/`--output`, `-t`/`--target`, `Long` description text

- **`-o`/`--output`**: wired through to `runBundleProducer`'s previously-hardcoded `OutputDir: filepath.Join(".", "build")` via a new `resolvePackOutputDir` helper. Exact Oracle help text (`commands/pack.py:206-211`, `"Bundle output directory (default: ./build)."`) — the Cobra/pflag flag default is deliberately `""` (not `"./build"`), since pflag auto-appends its own `(default "X")` annotation for any non-zero-value string default, which would double up with (and mismatch the format of) the literal text already baked into the help string; verified empirically that an empty pflag default produces no such auto-annotation. **Security**: apm-go now DELIBERATELY restricts `-o` to resolve within the project root, reusing `internal/marketplace/build.EnsureWithinRoot` — the SAME helper this exact function already calls one level down for `OutputDir`/`bundleRel` containment, and the same convention `internal/marketplace/authoring/refcheck.go`'s `resolveLocalSourceAgainstRoot` applies elsewhere. The Oracle places no such restriction on `-o` at all (a bare `click.Path()`); this is a stricter-than-Oracle hardening, documented as such at the deviation site, not a parity fix.
- **`-t`/`--target`**: wired through to the pre-existing `bundle.ProduceOptions.Target` field (previously hardcoded to `"all"`), which already flows into the embedded `apm.lock.yaml`'s `pack.target` metadata (`internal/pack/bundle/lockfile_pack.go`) — confirmed this is the SAME concept as the Oracle's `pack.target` (`commands/pack.py:356-360`). Exact Oracle help text (`commands/pack.py:177-183`). Deliberately does NOT replicate: (a) the Oracle's `detect_target()` auto-fill when `--target` is absent (`commands/pack.py:361-368`, a genuine auto-detection feature, not "wire an existing value through a flag" — the absent-flag default stays `"all"`, unchanged); (b) `TargetParamType`'s comma-separated multi-value parsing and `"copilot"`->`"vscode"` alias resolution (`target_detection.py:744-765`) — apm-go stores whatever single string is given, verbatim; (c) the Oracle's own deprecation warning printed when `--target` is explicitly given (`commands/pack.py:370-374`). All three are genuine "new logic" beyond this phase's stated scope, documented at the deviation site.
- **`Long` description text**: replaced apm-go's own three-bullet summary with the Oracle's `_PACK_HELP` docstring verbatim (`commands/pack.py:25-66`, `"apm"` -> `"apm-go"`) — the full text (usage examples, exit-code table), not just the first paragraph `help_semantic` actually compares. References `--archive`/`--check-versions`/`--check-clean`, none implemented yet (later phases) — textually accurate to the Oracle regardless, same as the Oracle's own docstring is unconditional on anything else in the file.

**Finding (not a new bug, already tracked)**: after this fix, `pack-help`'s `help_semantic` diff still shows `-t`/`--target`'s description as truncated on the Oracle's side ("...Bundles" with no continuation) even though apm-go's own text is confirmed byte-identical to the Oracle's live `--help` output (verified directly, `uv run apm pack --help`). Root cause: Click wraps this long description across 6 physical lines at terminal width, and the runner's `parseHelpFlags`/`parseFlagLine` (`tools/parity/help_semantic.go`) only captures a flag-spec line's own first physical line, silently dropping continuation lines. This is the SAME pre-existing, cross-cutting runner-parser limitation ticket 19 already documented ("the runner's own help_semantic parser not handling multi-line-wrapped flag descriptions... affects pack-help too") — not a new apm-go content gap, and not something this ticket's flag-implementation work should fix (a runner-tooling change, separate from this ticket's scope).

**Evidence**: `go build`/`go vet` clean. `go test ./...` all green. `go test ./cmd/apm-go/... -race -count=1` clean. Live-verified: `-o ./custom-out` writes the bundle there; `-o ../outside`/`-o /tmp/absolute-escape` both correctly rejected with "escapes the project root"; `-o ./dist` (the docstring's own example) succeeds; `-t claude` embeds `pack.target: claude` in a real `apm.lock.yaml` fixture; omitting either flag keeps the exact pre-ticket-17 default behavior (`./build`, `pack.target: all`). New tests: `TestPackCmd_OutputFlag_WritesToCustomDirectory`, `TestPackCmd_OutputFlag_DefaultsToBuildWhenNotGiven`, `TestPackCmd_OutputFlag_RejectsPathEscapingProjectRoot`, `TestPackCmd_TargetFlag_RecordsInEmbeddedLockfile`, `TestPackCmd_TargetFlag_DefaultsToAllWhenNotGiven`, `TestPackCmd_HelpMatchesOraclePackHelpDocstring` (replaces `TestPackCmd_HelpDocumentsThreeProducers`, which asserted the old self-authored text); `TestPackCmd_FlagsWired` extended for `-o`/`-t`/shorthands. Parity corpus: built pre-fix (`df43a31`, stashed) and post-fix binaries, ran all 69 cases against the pinned Oracle. Both report 1 of 69 unwaived (`pack-help` only, expected — 6 flags still missing). A tuple-level `(fields, waived)` diff across all 69 case ids: **zero changes** — every `pack-*` case, including `pack-help` itself, byte-for-byte unchanged.

## Suggested order (cheapest/most isolated first)

1. `-o`/`--output` (wire an existing hardcoded value through a flag; no new logic).
2. `-t`/`--target` (pure metadata field, Oracle already treats it as ignored/deprecated).
3. `--archive`/`--archive-format` (real feature, but self-contained: an archive-writing step after the existing directory bundle is built).
4. `--legacy-skill-paths` (a deploy-path variant, likely shares code with existing per-target skill placement logic).
5. `--check-versions`/`--check-clean` (release gates — depend on `marketplace.versioning.strategy` config and a temp-regenerate-and-diff mechanism; more design work).
6. `--json` (touches every success/error path in `pack.go`; do last so its envelope shape can capture whatever the other flags added).
