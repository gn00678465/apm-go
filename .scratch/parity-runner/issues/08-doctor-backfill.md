## Investigation findings (read before touching the fixtures)

- **GitPython import-time crash.** The pinned Oracle's `import git` (deps/github_downloader.py:16, deps/bare_cache.py:34) runs GitPython's mandatory import-time refresh (git/__init__.py:263-298 → git/cmd.py `Git.refresh`:741-905), which shells out to a bare `git version` (no dashes) *before* the Oracle's own CLI dispatch — and hence `doctor.py`'s own `try/except FileNotFoundError` (doctor.py:112-140) — ever runs. Confirmed empirically (`uv run --project .../apm apm doctor` with a broken `git` on PATH): if that bare probe fails for ANY reason, the whole CLI dies with an unhandled Python traceback (`ImportError: Failed to initialize: ...`) before `run_doctor` executes at all.
  - **Design consequence:** every fault-injection fixture except `doctor-git-missing` answers the bare `version` probe successfully and only fails the specific invocation doctor actually checks (`--version` for git, `ls-remote` for network) — this is what lets `doctor-git-nonzero`/`doctor-network-*` exercise doctor's OWN handling instead of an unrelated Oracle crash.
  - **`doctor-git-missing` is the one case that cannot dodge this**: git is genuinely absent from PATH (`path_exclusive: true`, an empty directory), so GitPython's own probe raises `GitCommandNotFound` → `ImportError`, and the Oracle crashes with a traceback while apm-go (no import-time git dependency) renders its normal table with both critical rows `[x]`. Both sides exit 1, but stdout/stderr are completely different. Judged **not** a gap in apm-go to fix — it is an Oracle-side precondition failure that isn't something `doctor.py` chose — so it's a recorded, waived deviation (`waivers.json`, taxonomy `F08`), not a bug hunt.
- **Two real, previously-latent apm-go bugs found and fixed** (surfaced only because this ticket is the first thing to ever exercise doctor's *failure* paths against a real subprocess):
  1. `cmd/apm-go/doctor.go`'s `runDoctor` returned `withExitCode(1, errors.New("critical environment check failed"))` on any critical-check failure, which `main()`'s root error handler printed as an extra `[x] critical environment check failed` line on stdout — the pinned Oracle's own `commands/doctor.py:26-30` does `sys.exit(exit_code)` with **no** extra message, ever. Fixed with a new `withSilentExitCode`/`isSilentExit` (`cmd/apm-go/exitcode.go`) that main()'s error branch checks before printing. Every `doctor-*` fault-injection case would otherwise have shown this bogus extra line.
  2. `checkMarketplaceConfig`'s "both apm.yml and marketplace.yml exist" branch printed its message in FULL, unbounded — the Oracle's outer `except MarketplaceYmlError as exc: config_detail = str(exc)[:120]` (doctor.py:227-229) truncates to 120 chars. Fixed by truncating apm-go's own message to 120 too. The truncated tail still differs by a few bytes from the Oracle's own truncation (apm-go's message says "apm-go", 3 chars longer than the Oracle's "apm", so the same 120-byte cutoff lands in a different place) — that residual is exactly the ticket's pre-approved "apm-go binary-name substitution ... any residual is waived per case/field" category (`doctor-config-both`'s waiver).
  3. **`execGit`'s timeout didn't actually bound wall-clock time** when the underlying `git` forks a child that outlives it and inherits the stdout/stderr pipe (`doctor-network-timeout`'s `hang` fixture: `sleep 600` as the script's last statement). `exec.CommandContext`'s default cancellation only kills the *direct* child; an orphaned grandchild still holding the pipe open makes `cmd.Run()`/`Wait()` block until that grandchild exits on its own — real git never does this, so it was invisible until this ticket's fault injection. Fixed with `cmd.WaitDelay` (`execGitWaitDelay = 1s`) in `execGit`, regression-tested directly (`TestDoctor_ExecGit_TimesOutDespiteOrphanedGrandchildHoldingPipesOpen`).
- **Duplicate-name detection fires at different points in the two implementations.** The Oracle's `_build_config` (yml_schema.py) rejects a duplicate package name *during loading*, so for a real file (not the Oracle's own mocked unit test) doctor's separate check 6 (`_find_duplicate_names`) never actually runs — the marketplace-config row itself fails first. apm-go's `LoadAuthoringConfig` has no load-time duplicate rejection (by design: it's shared with `apm pack`/`package add/remove/set`, none of which should gain a new hard-reject gate as a side effect of doctor's own evidence backfill), so its marketplace-config row succeeds and its own "defence-in-depth" `checkDuplicateNames` is what actually fires. Recorded as a structural (not wording) difference, waived and documented (`doctor-config-duplicate-names`'s waiver) rather than silently changed — closing it is a bigger, separate decision about `LoadAuthoringConfig`'s shared validation contract, out of this ticket's scope.

## Fault-injection fixture mechanism

- [x] The runner gains `case.path_prepend`: a fixture subdirectory placed at the front of `PATH` for both sides. (Pre-existing since ticket 10 attempt 2/3, per the orchestrator's note — not re-added here.) Ticket adds `FAKE_GIT_MODE`-driven behaviour on top of it: `ok` (default, `cases/doctor-healthy/path/git`'s own script, reused verbatim for token-present/absent and every `config-*` case), `nonzero`, `hang`, `dns-fail`, `auth-fail`, `not-found`, `tls-fail` — one shared script (`cases/doctor-git-nonzero/path/git`, copied byte-for-byte into every mode-driven case) that always answers bare `version` (see investigation notes) and dispatches on `$FAKE_GIT_MODE` for `--version`/`ls-remote`. `missing` is not a script mode: `doctor-git-missing/path/` is an empty directory (a real `git` absent, not merely failing) paired with a new `case.path_exclusive: true` field (see below). Each failure mode's stderr sample is real git output, captured live during this investigation (`dns-fail` against a nonexistent host, `auth-fail`/`not-found` against real GitHub paths, `tls-fail` against badssl.com's self-signed-cert endpoint) — not hand-typed text.
- [x] `case.path_exclusive` (new `Case` field, `tools/parity/case.go`/`runner.go`): when true, `PathPrepend`'s directory becomes the ENTIRE PATH instead of merely leading it. Needed because an empty leading PATH entry does not hide a real `git` further down an inherited PATH (verified: `exec.Command`/`subprocess.run` both keep searching). Unit-tested (`TestRunCaseSide_PathExclusive_HidesRealBinary`).
- [x] `case.timeout_s` (new `Case` field): overrides the runner's default per-run kill-timeout for a case, in seconds. `doctor-network-timeout` sets this to 8 — strictly greater than doctor's own internal 5s check timeout plus apm-go's new 1s `WaitDelay`, so the product's own graceful timeout handling fires first on both sides; the outer timeout is only a backstop. Unit-tested at both the `runCaseSide` level (`TestRunCaseSide_TimeoutS_OverridesPerCase`) and the `runCaseAllSides` wiring level (`TestRunCaseAllSides_TimeoutSOverridesConfigTimeout`).
- [x] `case.forbid_substrings` (new `Case` field): after a side's run, the runner scans that side's raw stdout, raw stderr, and every "file" tree entry's on-disk content (before sandbox cleanup) for each listed substring, failing the whole run closed if found (`checkForbiddenSubstrings` in `runner.go`). Fail-closed: a match aborts the run the same way a non-zero `setup_argv` does. Unit-tested for all three surfaces plus a clean-run negative (`TestCheckForbiddenSubstrings_*`). Used by `doctor-token-present` to assert its fixed literal `GITHUB_TOKEN` value never appears anywhere in either side's output.
